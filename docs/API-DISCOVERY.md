# Как найден API журнала (законная методика)

Этот документ описывает, **как именно** было обнаружено API — воспроизводимые шаги
без чего-либо противозаконного: никаких взломов, обходов защиты или доступа к чужим данным.
Только анализ публично распространяемого кода и наблюдение за собственным аккаунтом.

## Исходная точка

Сайт [journal.top-academy.ru](https://journal.top-academy.ru) — личный кабинет студента.
Задача: получать **свои же** данные (оценки, расписание, ДЗ) в машиночитаемом виде,
не занимаясь хрупким парсингом HTML.

## Шаг 1. Веб-инспектор: есть ли XHR?

1. Открыть сайт в браузере, войти в **свой** аккаунт.
2. DevTools → Network → фильтр XHR/Fetch, полистать страницы дневника.

Вывод: страницы серверные, собственных XHR почти нет — но в загрузках виден
единый JS-бандл приложения `app.<hash>.js`.

## Шаг 2. Анализ публичного JS-бандла

Бандл загружается в браузер каждому посетителю — это публично распространяемый код
(эквивалент «программы в коробке», которую вы легально купили и изучаете).

1. Сохранить `app.*.js` (DevTools → Sources → Save, или просто `curl`).
2. Поиском по строкам найти `apiUrl`, `"/auth/login"`, `"application_key"`:

```
grep -o 'https://msapi[a-z./-]*' app.js
# → https://msapi.top-academy.ru/api/v2

grep -o 'new [A-Za-z]*\.AuthModel("[0-9a-f]\{64\}")' app.js
# → new r.AuthModel("6a56a5df2667e65aab73ce76d1dd737f7d1faef9c52e8b8c55ac75f565d8e8a6")
```

Из бандла также извлекаются все пути эндпоинтов (`/progress/operations/student-visits`,
`/homework/operations/list`, …), enum'ы статусов и структура модели авторизации.

## Шаг 3. Подтверждение запросами своего аккаунта

Далее — обычные HTTP-запросы со **своими** логином и паролем (те же, что вводятся
в браузере). Ничего не брутфорсится, никто не притворяется чужим клиентом:

```
curl -X POST https://msapi.top-academy.ru/api/v2/auth/login \
  -H "Content-Type: application/json" \
  -H "Referer: https://journalka.top-academy.ru/" \
  -d '{"username":"<свой логин>","password":"<свой пароль>",
       "application_key":"6a56a5df2667e65aab73ce76d1dd737f7d1faef9c52e8b8c55ac75f565d8e8a6"}'
```

Особенность: WAF (DDoS-Guard) пускает только запросы с заголовком
`Referer: https://<поддомен>.top-academy.ru/`. Никакой «защиты» это не обходят —
это просто обязательный заголовок, который шлёт и официальный клиент.

## Почему это законно

- **Публичность кода**: JS-бандл открыто раздаётся каждому браузеру; его чтение —
  то же, что чтение любой открытой веб-страницы.
- **Интероперабельность**: анализ форматов и протоколов для совместимости —
  общепризнанная практика (в ЕС прямо разрешена директивой 2009/24/EC ст. 6;
  в РФ и США добросовестный реверс-инжиниринг для совместимости не запрещён).
- **Свои данные**: запрашивается только информация собственного аккаунта,
  с собственными учётными данными, теми же запросами, что отправляет
  официальный клиент (приложение MyStat в Google Play / App Store).
- **Никакого вреда**: частота опроса — не чаще одного раза в 15–30 минут
  (реже, чем открытие сайта человеком), никаких попыток обойти лимиты или
  получить доступ к чужим данным.
- `application_key` — не секрет: он вшит в публичный бандл и одинаков для всех
  пользователей, это идентификатор приложения, а не чей-то пароль.

## Что НЕ делалось (и не нужно)

- Не декомпилировался APK MyStat (хотя и это для интероперабельности допустимо) —
  хватило веб-бандла.
- Не использовались чужие учётные данные, не сканировались чужие аккаунты.
- Не обходились капчи, лимиты или блокировки.
